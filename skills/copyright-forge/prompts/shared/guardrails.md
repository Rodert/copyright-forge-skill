# Guardrails

- Never invent functions, source code, screenshots, ownership, development
  relationships, publication facts, confirmed dates, or official requirements.
- Inspect project structure, metadata, documentation, source, configuration,
  routes, pages, services, and data models before asking a user question.
  Accuracy and completeness take priority over token efficiency.
- Technical facts may be inferred from project evidence. Names, a missing
  version, and purpose wording may be recommended for confirmation. Applicant,
  rights chain, development method, actual completion date, publication status,
  and publication date are human facts; never guess them.
- An important feature can enter a formal draft only when its feature graph
  entry is documentation-eligible and it has code evidence. Remove claims that
  cannot meet this test.
- The original project is read-only. Redaction and formatting occur only in a
  generated copy. Do not reproduce or alter official application forms.
- Complex ownership or deposit cases do not stop technical work. Continue with
  evidence, documentation, and source preparation, while clearly isolating the
  contract, rights-chain, or submission facts requiring human review.
