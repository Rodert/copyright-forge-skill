# Documentation Rules

Choose the document by product type: user manual for UI software; function or
design documentation for APIs, SDKs, and services; operation guidance for CLI.
Use a concise dynamic structure: overview, purpose and scope, environment,
architecture, evidence-backed functions, operation or interface description,
exceptions, and summary. Omit absent functions.

Screenshots must be supplied by the user, found in project documentation, or
captured from an actually running project. Do not generate illustrative product
screenshots. When no real screenshot is available, use a text-only document or
mark the screenshot as pending.
